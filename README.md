# Amazon ML Challenge 2026 — Final Pipeline

## Final production policy

The final production submission uses the already-built V6 + V9.1
candidate pool and V10 pairwise ranking model.

For each Source-1 record:

1. Score the complete candidate pool for Source 2 and Source 3.
2. Rank independently within each target source.
3. Keep only the rank-1 candidate from each target source.
4. Accept that rank-1 candidate only when:

       v10_utility >= 20.945884704589844

5. Otherwise emit no match for that target source.

This produces at most one S2 match and at most one S3 match per
Source-1 entity.

## Candidate generation

The final test candidate pools are the candidate sets generated by the
existing production baseline:

- V1 exact composite keys
- V2 postal blocking
- V4 selected address/postal blocks
- V5 structured name/postal and address/postal blocks
- V9.1 numeric-address + name-prefix blocking

The exact candidate Parquet pools used for inference are:

- test_candidates_s1_s2.parquet
- test_candidates_s1_s3.parquet

`candidate_pairs.tsv` is generated from those exact model-input pools.

## Model

Two separate pairwise LogisticRegression rankers are used:

- S1 -> S2
- S1 -> S3

The V10 feature set is:

name_similarity,
address_similarity,
name_exact,
address_exact,
country_exact,
name_length_ratio,
address_length_ratio,
evidence_rows,
evidence_file_count,
exact_key_count,
base_score,
log_base_rank,
name_x_address,
name_minus_address,
similarity_mean,
similarity_min,
exact_field_count

The vectors are standardized before LogisticRegression.

Training uses pairwise positive-vs-negative examples constructed from
the labelled training candidate pool.

## Base score

The transparent base score is:

30 * name_exact
+ 25 * address_exact
+ 8 * country_exact
+ 22 * name_similarity
+ 12 * address_similarity
+ 2 * name_length_ratio
+ 1 * address_length_ratio
+ 0.75 * evidence_file_count (clipped at 4)
+ 0.25 * exact_key_count (clipped at 5)

## Threshold selection

The threshold was selected on the old V7 validation split using a
model trained only on the non-validation Source-1 entities.

Baseline K1/K1:

macro F0.5 = 0.594111908498

Optimized Top-1 + abstention:

threshold = 20.945884704589844
macro F0.5 = 0.617515903939

The threshold was frozen before final test output generation.

The V8-expanded candidate architecture was separately audited. It
improved retrieval recall but reduced the precision-heavy validation
F0.5 under the audited prediction policy, so the final production
candidate pool remains the V6 + V9.1 pool.

The locked Final Holdout V2 was not used for threshold tuning.

## Data integrity

Only the supplied challenge data and internally derived features are
used. No external business identity lookup, external database,
geocoding API, or external business-data augmentation is used.

Country is treated as an open-set string label; no US/India-only
filtering is used.

## Required outputs

output/matching_results.tsv
output/candidate_pairs.tsv

Every Source-1 test entity appears exactly once in matching_results.tsv.

Empty matched_entity_ids represents abstention/no predicted match.

Every predicted ID comes from the final candidate set.
